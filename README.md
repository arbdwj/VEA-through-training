# VEA through training

Companion code, data, and figures for **"Tracing Eval-Awareness Emergence Through OLMo-3 Training"** — where in the training pipeline does verbalized evaluation-awareness (VEA) come from?

We measure VEA (Goodfire Appendix F1 rubric, applied to the chain-of-thought before `</think>`; a rollout is VEA if the judge returns a non-`None` quote) across the full OLMo-3 training pipeline — pretraining checkpoints → SFT → DPO → RLVR — on 5 safety benchmarks (444 prompts × 8 rollouts each). Headline findings:

- **VEA is essentially absent during pretraining (~1%)** — it is installed by post-training.
- Across post-training it is **installed by SFT, stripped by DPO, and rebuilt/amplified by RLVR**.
- Behavioral eval-gaming (refusing more when eval-aware), measured **within-question**, is small and not individually significant; pooled estimates overstate it (matches Goodfire's within-question +3–18 pp with our +4–20 pp).
- The first VEA token lands in the first third of the CoT (median ~187 tokens) but is **broad / stochastic** — no sharp positional trigger; the only clean structure is that **blunter prompts trip VEA earlier**.

The write-up is in [`post.md`](post.md) (LessWrong-formatted Markdown) and [`paper/vea_training.pdf`](paper/vea_training.pdf) (formal version).

```

paper/                   # formal version: vea_training.tex + .pdf
figures/                 # fig1–fig7 (regenerated by scripts/)
scripts/                 # one self-contained script per figure (read ../data, write ../figures)
  _paths.py  _stats.py   # path resolution + by-prompt cluster bootstrap
  fig1_pretrain_vea.py ... fig7_first_vea_by_benchmark.py

```

## Reproduce the figures
Needs `numpy pandas matplotlib scipy` (and `pdflatex` for the PDF). Figures regenerate from the bundled `data/` alone — no GPU or API needed:
```bash
python -m venv .venv && ./.venv/bin/pip install numpy pandas matplotlib scipy
PY=./.venv/bin/python ./build.sh         # figures + PDF
# or a single figure:
cd scripts && ../.venv/bin/python fig1_pretrain_vea.py
```

## Data
- `*_vea*.jsonl` — per-rollout VEA judgments (`step`, `benchmark`, `prompt_id`, `rollout_id`, `ok`, `vea`, `quote`).
- `refusal_haiku.jsonl` — per-rollout refusal + VEA labels (Haiku F2), for the eval-gaming figure.
- `vea_first_token.csv` / `vea_position*.csv` — derived first-VEA-token positions (Gemini earliest-span located in the CoT and counted with OLMo-3's tokenizer).
- `pretrain_rollouts/*.jsonl` — base-model completions for the 5 stage1 pretraining checkpoints (the only large files; needed by Fig 1 for `</think>` rates).
- `prompts/` — the 444 safety prompts.

## Pipeline (`pipeline/`, reference only)
Upstream scripts that produced the data — these require Modal GPUs and OpenRouter API access and read the original raw rollouts, so they are included for provenance, not turnkey re-execution:
- `modal_app_base_pretrain.py` — vLLM sampler for the pretraining checkpoints.
- `judge_vea.py` — core F1 VEA judge (the exact rubric + CoT extraction); imported by the others.
- `judge_pretrain_vea.py` — VEA judging of the pretraining rollouts (Gemini-2.5-flash).
- `analyze_vea_position*.py`, `refine_vea_first_token.py` — first-VEA-token location (Gemini earliest-span + exact OLMo-3 tokenizer).

## Caveats (see post §Limitations)
- **Clustered CIs.** Rollouts are nested in prompts (ICC ≈ 0.45); error bars in Figs 1–2 are by-prompt cluster-bootstrap 95% CIs, not naive Wald. Trends survive; fine checkpoint-to-checkpoint differences may not.
- **Judge consistency.** `gpt-5-mini` (RLVR, SFT, DPO), `claude-haiku-4.5` (BASE, refusal), `google/gemini-2.5-flash` (pretraining). Cross-judge comparisons (BASE vs others; pretraining vs post-training) are reference-only.
- **Pretraining context.** stage1 checkpoints have a native 8192 context (post-trained models are extended to 20480) and emit no stop token, so the pretraining sweep used a 2048-token cap; VEA is verbalized early so this does not bias detection.
